# RSW v0.2.19

Минимальный автоматический переключатель русской/английской раскладки для macOS
на Apple Silicon. Приложение живёт в строке меню, хранит только текущее слово и
не использует сеть.

## Установка

### Быстрый старт (make)

```bash
make build           # release-сборка
make test            # 334 теста
make install         # установить в /Applications
make install LOGIN=1 # + зарегистрировать login item
make uninstall       # удалить .app и login item
make clean           # очистить build/ и .build/
```

### Прямой запуск скриптов

```bash
./install.sh                # установить в /Applications и зарегистрировать login item
./install.sh --no-login     # без автоматического запуска при входе
./install.sh --prefix ~/Apps  # установить в пользовательский каталог
./run.sh --release          # release-сборка, запуск
./run.sh --test             # только тесты
./uninstall.sh              # удалить .app
./uninstall.sh --purge      # + удалить словарь и логи
```

Скрипт `install.sh`:
1. Собирает `swift build -c release`.
2. Упаковывает бинарь в `.app-бандл` с минимальным `Info.plist`
   (`LSUIElement = true` — без иконки в Dock, `NSHighResolutionCapable = true`).
3. Копирует в `/Applications/RSW.app`.
4. Регистрирует login item через AppleScript (`System Events`).

При **первом** запуске macOS попросит доступ в
**System Settings → Privacy & Security → Accessibility**.
После выдачи доступа — запустите приложение ещё раз.

Запуск: `open /Applications/RSW.app` или двойной клик в Finder.

## Запуск в режиме разработки

```bash
swift run rsw            # debug-сборка, запуск
./run.sh --release       # release-сборка, запуск
./run.sh --test          # только тесты (334 проверки)
```

Неверно набранное слово исправляется после пробела или знака препинания. Например:

- `ghbdtn` → `привет`
- `руддщ` → `hello`

Переключение можно временно отключить через значок клавиатуры в строке меню.

## Как работает исправление

RSW отслеживает только текущее набираемое слово. Когда пользователь нажимает
пробел или знак препинания, приложение проверяет слово через `SwitcherCore` и,
если уверенность достаточная, заменяет слово перед курсором.

Для обычных редакторов используется Accessibility API:

- читается активный AX-элемент и позиция курсора через `kAXSelectedTextRangeAttribute`
- заменяется только диапазон слова перед курсором
- разделитель (`пробел`, `.`, `,` и т. п.) вставляется вместе с исправленным словом,
  чтобы не зависеть от порядка доставки исходной клавиши в приложение

Если AX-замена недоступна, автоисправление отменяется и исходная клавиша
передаётся приложению без изменений. Это лучше, чем менять текст вслепую и
рисковать удалить или вставить не то слово. RSW не использует синтетический
ввод для автоисправления: только подтверждённые AX-замены.

## Терминалы

RSW полностью отключается в терминальных приложениях. В Terminal, iTerm2, Warp,
Ghostty, Kitty и Alacritty приложение не исправляет текст, не буферизует ввод,
не переключает выделение и не меняет раскладку.

Это намеренное ограничение: терминалы ненадёжно позволяют менять текущую
командную строку через Accessibility, pasteboard или синтетические события.
Вместо рискованной замены RSW пропускает все события клавиатуры как есть.

## Безопасная архитектура v0.2.19

Текущая стратегия: лучше не исправить слово, чем исправить не то. Поэтому:

- автоисправление применяет только подтверждённую AX-замену;
- общий буфер обмена (`NSPasteboard`) не используется для исправлений;
- меню Paste не вызывается;
- терминальные приложения работают только в pass-through режиме;
- если AX не подтверждает позицию курсора, исходный ввод остаётся без изменений.

### App-level политики

RSW применяет allow/deny-логику к Electron-приложениям, где AX часто
ненадёжен. В настройках («Приложения») можно:
- включить/выключить проверку;
- добавить текущее приложение в белый список;
- видеть список разрешённых bundle identifiers.

Для не-Electron приложений автоисправление разрешено по умолчанию.

### ConversionDecision debug API

Внутренний `ConversionBuilder` возвращает детализированное решение:
- outcome (auto / fallback с причиной);
- convertedText, source/target language;
- sourceScore, targetScore;
- dictionaryHit и rejectionReason.

Это позволяет строить табличные FP/FN-тесты на основе диагностических логов
и тонко настраивать пороги без изменения production кода.

### Встроенные словари

Built-in словари вынесены в JSON-ресурсы (`Sources/SwitcherCore/Resources/`):
- `english_dictionary.json`
- `russian_dictionary.json`

При запуске они загружаются через `Bundle.module` и объединяются с
пользовательским словарём из `~/Library/Application Support/RSwitcher/words.json`.

Подробный план рефакторинга и улучшений: [docs/REFACTORING_PLAN.md](docs/REFACTORING_PLAN.md).

## Настройки

Окно настроек (значок в строке меню → «Настройки…») содержит пять вкладок:

- **Основные** — автопереключение, минимальная длина слова, подсказка при
  исправлении, запуск при входе в систему
- **Горячие клавиши** — комбинация для ручного переключения выделенного текста
- **Исключения** — клавиши, не сбрасывающие текущее слово (например, Shift)
- **Приложения** — Electron allow-list policy: включить/выключить, добавить
  текущее приложение, список разрешённых bundle identifiers
- **Словарь** — добавление слов и статистика

> **Запуск при входе в систему** работает только для подписанного `.app`-бандла
> (через `SMAppService`). При запуске raw-бинаря из `swift run` регистрация login
> item невозможна.

### Словарь слов

Для повышения точности используется словарь известных слов. При исправлении,
если конвертированное слово есть в словаре целевого языка — оно исправляется
с высокой уверенностью.

Добавить слово в словарь можно через меню:
- **Добавить последнее слово** — сохраняет слово, которое только что было исправлено
- **Добавить слово вручную** — ввод произвольного слова

Словарь хранится в `~/Library/Application Support/RSwitcher/words.json`.

## Диагностика

Подробные runtime-логи отключены по умолчанию, чтобы запуск из Терминала не
загрязнял активный терминальный буфер и не мешал AX-замене.

Для короткой диагностики stderr запустите:

```bash
RSW_DEBUG=1 swift run rsw
```

Для длительной диагностики на несколько дней используйте JSONL-логи:

```bash
RSW_DIAG=1 swift run rsw
```

По умолчанию файлы пишутся в `~/Library/Logs/RSW/` с именами вида
`rsw-diagnostics-YYYYMMDD-HHMMSS-SSS.jsonl`. Каждый файл ротируется при
достижении 25 MB.

Меню «Открыть текущий лог» (значок в строке меню) показывает последнюю ошибку
(`correction_failed` / `manual_switch_failed`) из JSONL-лога в alert перед
открытием папки с логами.

Настройки диагностического режима:

- `RSW_DIAG=1` — включает структурированные JSONL-логи
- `RSW_DIAG_CAPTURE_TEXT=1` — пишет полный текст клавиш, текущее слово,
  выделенный текст и AX-заголовки без редактирования
- `RSW_DIAG_DIR=/path/to/dir` — меняет директорию логов
- `RSW_DIAG_MAX_MB=50` — меняет размер файла до ротации

События в JSONL:

- `keyboard_event` — keyCode, flags, тип CGEvent, активное приложение,
  терминальный режим, решение обработчика
- `focused_ax` — роль/подроль/идентификатор активного AX-элемента и диапазон
  выделения
- `correction_accepted`, `correction_applied`, `correction_failed` — решение
  конвертера и путь замены
- `manual_switch_*` — ручное переключение, выделение и fallback
- `memory` — периодический snapshot памяти и CPU-времени процесса
- `event_tap_*` — запуск и переактивация event tap

> `RSW_DIAG_CAPTURE_TEXT=1` записывает фактический ввод пользователя. В таких
> логах могут оказаться пароли, токены, команды, сообщения и содержимое
> выделенного текста. Включайте этот режим только для локальной диагностики и
> не отправляйте такие логи без ручной очистки.

Если исправление не работает в конкретном приложении:

- проверьте, что RSW есть в **System Settings → Privacy & Security → Accessibility**
- перезапустите RSW после выдачи Accessibility-доступа
- терминальные приложения намеренно исключены из обработки
- проверьте `RSW_DIAG=1 swift run rsw`, чтобы увидеть причину `correction_failed`

Для приложений, где AX не подтверждает позицию курсора (некоторые Electron-редакторы),
автоисправление временно недоступно. Ручное переключение выделенного текста
работает через AX и не требует synthetic fallback.

> Тесты запускаются через цель `TestRunner` (`swift run TestRunner`), а не через
> `swift test`. Стандартный `swift test` требует модуль `XCTest`, который
> поставляется только с полным Xcode; на машине с одними Command Line Tools он
> недоступен. `TestRunner` — самодостаточный набор тестов, не зависящий от XCTest.
> XCTest-набор в `Tests/SwitcherCoreTests` сохранён для запуска под Xcode.

`TestRunner` использует изолированный словарь в памяти и не меняет пользовательский
файл `~/Library/Application Support/RSwitcher/words.json`.

Это компактная версия: она использует эвристику частотных сочетаний букв,
поэтому намеренно исправляет только слова с высокой уверенностью.
